# Contributing

Same flow as the rest of this repo family: fork, feature branch, commit,
PR.

## Style guide specific to this repo

- This is architecture content, not theory (→ `rnd-ai-ml-llm`) and not
  testing (→ `ai-test-engineering-career-prep`) — if a draft is really
  explaining *how something works* rather than *how to design it in
  production*, it belongs in one of those instead, linked from here.
- This field changes fast. Every doc should carry the same "Best
  Practices over unverifiable specifics" discipline as the rest of this
  repo family — durable architectural judgment over version-specific
  claims about any one framework or serving engine.
- Case studies follow the flagship repo's `_TEMPLATE.md` exactly —
  requirements → design → deep dive → failure modes → Best Practices /
  What we'd do differently.
